# Breakthrough on Netlify

The November 2 source deployed successfully, but public admission was closed and the Netlify API did not attach the persistent-process room service. This change adds a Netlify runtime without moving the game to another provider.

Each active room uses one signed background invocation, bounded to twelve minutes (room expiry is ten minutes). The existing fenced owner advances authoritative time, journals commands before acknowledging them, batches clock journals, and settles the existing outbox. A ten-second database dispatch reservation prevents duplicate invocation bursts. Duplicate workers lose the room lease. A once-per-minute recovery function restarts expired room owners and drains terminal receipts; normal play starts immediately through the queue.

The API uses Web Response streaming instead of its buffered Express adapter for Breakthrough. Each connection closes before forty-five seconds/token expiry and reconnects with a private baseline. The live Netlify database did not deliver the cross-connection LISTEN/NOTIFY probe on deployed revision 7760c12c. Netlify therefore uses compressed SQL mailboxes: commands are checked every 100ms and stream messages every 200ms; per-seat deltas publish at most five times per second. Rows expire after 30 seconds, are deleted when read or closed, and abandoned rows are cleared each minute. Ordinary persistent hosts retain the notification option. Mailbox transport is ephemeral: only the existing journal defines command acceptance. Unknown outcomes retain the browser's original command identity. Two streams per participant, per-account request budgets, bounded frames and slow-reader disconnection limit retained work.

The runtime uses ordinary transactional Postgres queries through Netlify's database proxy. Initial production capacity is bounded to 20 simultaneous matches. The immutable catalog acceptance decision is cached per process, outside the clock loop. `/api/breakthrough/status` tests actual cross-connection transport delivery, required schema, runtime configuration and the catalog release gate. It returns only non-secret readiness information and build identity. Do not enable player admission if the hosted transport test fails.

Configuration: functions-scope `BREAKTHROUGH_PVP_ENABLED=true` and a random secret of at least 32 characters in `BREAKTHROUGH_WORKER_SECRET`. Background dispatch signs its exact body and timestamp. Existing Clerk authentication, same-origin checks, owned-deck admission and PostgreSQL configuration remain in use. Mirrored migrations add a worker-dispatch timestamp and a private expiring transport table with row-level security.

Verification: `node scripts/test-breakthrough-database.mjs --netlify`, the packaged-function check, native migration replay and the required frozen-source build gate. These local checks do not establish hosted transport, live Clerk sessions, provider latency, billing or physical-phone behavior. Public catalog approval/evidence remains unchanged until its separate acceptance work is complete.
