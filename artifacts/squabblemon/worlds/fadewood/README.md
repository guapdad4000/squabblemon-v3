# Fadewood integrated runtime

Imported from the user-supplied `fadewood-integration-source.zip` on 2026-10-30. Scene artwork, rigs, named animation clips, collision physics, railway, sky, residents, and authored camera/travel composition remain editable source. The follow camera also checks live portal artwork with a small swept clearance so Alice's moving hat cannot clip the initial view. The archive is source material; application/account authority comes exclusively from Squabblemon.

## Build and tests

This is a separate Vite/Three.js 0.184.0 runtime, loaded by the account app only on Fadewood entry. From this directory, install the pinned lockfile with `npm ci`, run `npm run build`, and `npm test && npm run test:bridge && npm run test:refinements`.

`node scripts/build-integrated.mjs` rebuilds `../../public/scenes/fadewood/index.html`. Assets are owned once at `../../public/scenes/fadewood/assets`; `public/assets` is a relative symlink for editable-source development and collision tests. The build retains authored art and removes only generated JS/CSS before rebuilding. It copies the Three.js MIT notice into the public runtime and writes source/output SHA-256 hashes to `source-manifest.json`. Run `node scripts/runtime-integrity.mjs --check` as a dependency-free release gate; it fails for stale source, missing art/chunks, or modified build output. No character masters or browser test fixtures ship.

The optional original-master equivalence audit requires external authoring files and is explicitly skipped by the default runtime test command. Set `FADEWOOD_AUTHORING_ROOT` to the extracted archive root, `FADEWOOD_SOURCE_ASSETS` to the source archive's `playable/public/assets` and `FADEWOOD_SOURCE_AUDIT` to its `outputs/mobile-asset-audit.json` to run it. The original 23 runtime suites remain available. The integrated bridge suite tests origin/source/nonce boundaries, malformed checkpoints, source-only interaction intents, presentation bounds, grounded semantic arrivals, and 225 camera/cloud collision routes using the active shipped world, entrance meshes, six vehicle proxies, curb booth, and relocated hoop. These are local geometry/logic checks, not physical-device or production performance proof.

## Host contract

Embed `/scenes/fadewood/index.html?host=1`. The envelope is `{channel:'squabblemon-fadewood', version:1, instanceId, type, ...payload}`. The host repeats `init {reducedMotion, night?, checkpoint?}` until `ready`. The child validates same origin, `event.source === parent`, and the established instance nonce before handling commands. `ready` is emitted after essential textures, all cast, collision, and initial shader compilation. Commands: `lighting`, `mode`, `travel`, `cancelTravel`, `focus`, `releaseFocus`, `restore`, `presentation`, `dispose`. Events: `progress`, `ready`, `state`, `inspect`, `travelComplete`, `travelCancelled`, `focusComplete`, `focusCancelled`, `lighting`, `error`.

`presentation {storyTargets:[{arcId,sourceId,label}],mail?:{unread,gifts,attentionId?,opened?}}` accepts at most 24 entries and known actor/portal IDs. The child projects moving actor positions into `state.markers` normalized 0..100 X/Y, with `visible` indicating the camera frustum; labels and click behavior belong to the parent. Mail counts add a marker on the live Mailman. Projected labels do not currently test world occlusion. State emission is bounded to roughly 4.5 Hz; rendering uses no extra marker loop.

The integrated page contains canvas and touch locomotion controls. It loads the existing Hemi Head button font from the game source. It does not mount standalone demo menus/conversations/fonts; all player prompts, fast-travel lists, loading/errors, dialogs, account receipts, and notification overlays belong to the parent. E emits the nearest source ID; F and Escape emit `world-map`/`world-pause`. No arbitrary route or API intent is accepted from scene geometry.

## Current limits

The initial full scene is approximately 58.6 MB of runtime assets (world, cast, and delivered additions), route-lazy loaded. The imported renderer already caps DPR, uses compact resident assets, limits model load concurrency, and batches environmental artwork. Progressive district streaming, device-tier LOD, GPU compression, and measured physical-device budgets remain future optimization work. Do not label this a completed AAA optimization pass. Character customization has no asset/reward authority here and will require the separate approved avatar contract before models or palettes are switched.


## Character focus, courier attention, and bulletin board

The host sends `focus {requestId,sourceId}` after `mode:'exploring'`. The child interpolates into the existing authored character/portal camera shot for .85 seconds, locks movement, and emits `focusComplete {requestId,sourceId}` only on the final frame. Reduced motion reaches the final shot immediately. The completed shot remains held through host overlay mode. `releaseFocus {requestId?}` restores exploration framing. Unknown targets emit `focusCancelled` with `reason:'unavailable'`; interrupted in-flight framing emits `reason:'cancelled'`. Paused/overlay/suspended/hidden states invalidate unfinished focus, while repeated exploring commands cannot unlock or reset an active focus. Host resume does not steal keyboard focus from the popup opener.

Short local clicks/taps on actual character meshes, portal props, or the park board emit inspect intents. Looking/dragging does not click; a first visible scene hit and a six-metre interaction reach prevent through-wall or remote selection. This is a click-time raycast with no new frame loop.

`presentation.mail` optionally includes a bounded, account-scoped `attentionId` and `opened` boolean. Pending mail queues one courier visit only during safe exploration. The existing Mailman flight/landing/idle clips move his original rig along a capsule-checked path, to a solid landing at least 2.8m from the player, preferring the far side of the avatar from the current camera before safe alternate approaches. Loading, travel, framing, and dialogs defer flight. A blocked arrival, retarget, or return retries at most about once a second, with an immediate retry for a new attention batch or a player move of at least two metres. He waits at the landing until mail is opened/read/claimed; no courier motion opens a popup. Only acknowledged attention identities are stored in optional session presentation memory. Landing does not acknowledge a batch: the active waiting visit prevents repeat takeoffs in the current scene, new attention joins that visit, and unread/unopened attention can visit again after leaving and re-entering the world. Opening mail, completing Mailman focus, or clearing the pending attention acknowledges the batch; acknowledged identities do not nag on later entry. Claims and balances remain host/server-owned.

The obsolete source Fade Park placard at `[18,2.65,-16.15]` is repurposed only for integrated mode. Its original navy frame and timber posts remain; the accessible park-side face receives cropped existing cork and three canonical event-art flyers, preserving their proportions. The separate compact park entrance plaque stays unchanged. The four existing images use quality-95, aspect-preserving delivery derivatives: cork is at most 1024px, each flyer at most 512px. `scripts/build-bulletin-art.py` reproduces them with Pillow/LANCZOS; `assets/bulletin/provenance.json` records original/output dimensions, byte counts, and SHA-256 hashes. The face adds fourteen static, non-collision triangles in five draws, with no new structural board. `fade-park-bulletin` is the known source and safe destination; interaction feet are `[18,.3635,-18]`, and the host owns its Events/bounties popup and navigation. No new artwork was generated; the host marker carries the Events & bounties label above the physical flyer board.
